# [Context Summary] Planning Specification for Agent: PLAN.json

### 1. 설계 배경 (Core Motivation)
- **토큰 효율성 최적화:** AI 에이전트가 반복적인 루프를 수행할 때마다 거대한 마크다운(MD) 파일을 전체 읽기/쓰기 함으로써 발생하는 기하급수적인 토큰 낭비와 비용 문제를 해결하고자 함.
- **데이터와 표현의 분리:** 에이전트에게는 기계 판독이 용이하고 부분 업데이트가 가능한 구조화된 데이터를 제공하고, 인간에게는 시각적으로 친숙한 문서 형태를 제공하는 하이브리드 인터페이스를 지향함.

### 2. 핵심 개념 (Core Concept)
- **구조화된 계획 관리:** 계획 문서의 모든 요소를 객체화하여 관리함으로써, 에이전트가 `jq`나 특정 키 경로(Key-path)를 통해 필요한 정보(Phase, Status 등)에 $O(1)$ 수준으로 접근하고 수정할 수 있게 함.
- **상태 중심 설계:** 단순 기록이 아닌 에이전트의 현재 실행 상태(State)와 로드맵(Phases)을 동적으로 반영하는 데이터 모델을 구축함.

### 3. 기술 스펙 정체성 (Identity)
- **확장자 (`.jsonmd`):** `JSON`의 엄격한 데이터 구조와 `Markdown`의 표현력을 결합한 독자적인 포맷. 실제 파일은 JSON 형식을 유지하되, 그 본질은 마크다운 문서를 구성하기 위한 소스 데이터를 담고 있음.
- **프로젝트 (`PLAN.json`):** 에이전트가 작업 계획을 수립, 실행, 추적하기 위해 사용하는 전용 데이터 관리 시스템 및 워크플로우를 통칭함.
- **스펙 (`Planning Specification for Agent`):** 에이전트가 계획 파일을 파싱, 이해, 업데이트하기 위해 준수해야 하는 필드 정의 및 상태 전이 규칙의 표준화된 규격.

### 4. 사용자 경험 (Developer Experience)
- **에이전트 관점:** 불필요한 마크다운 구문(Syntax)을 제외한 순수 데이터 노드만 처리하여 입력/출력 토큰을 최소화하고, 정보 밀도를 극대화함.
- **인간 관점:** 전용 확장 프로그램(VS Code 등)을 통해 JSON 데이터를 실시간으로 렌더링된 마크다운 미리보기로 확인하며, 에이전트의 진행 상황을 직관적으로 모니터링함.
